# 系统测试报告

## 1 测试概述

### 1.1 测试目的

验证“武陵山区果园管理系统”是否满足需求分析中确定的验收标准，重点检查：

1. 前台页面是否完整、可访问、无脚本错误；
2. 购物、下单、取消、确认收货等核心业务是否闭环；
3. 后台登录、看板、CRUD、订单流转、留言回复、预约确认是否正常；
4. 库存、金额、订单状态等关键数据是否一致；
5. 桌面端与移动端布局是否可用；
6. 权限控制、输入校验和异常提示是否有效。

### 1.2 测试范围

| 范围 | 内容 |
|---|---|
| 前台 | 首页、果园列表/详情、产品列表/详情、资讯列表/详情、关于、联系、登录、注册、购物车、结算、下单成功、个人中心 |
| 后台 | 登录、数据看板、订单、产品、果园、预约、资讯、用户、留言、设置 |
| 数据 | 初始化、增删改查、库存扣减/恢复、金额计算、状态日志、导入导出（接口层） |
| 非功能 | 响应式、图片加载、链接完整性、控制台错误、性能、浏览器兼容性 |
| 安全 | 未登录访问后台、普通用户越权、手机号/密码校验、HTML 转义 |

### 1.3 测试环境

| 项目 | 配置 |
|---|---|
| 操作系统 | Windows 11 Pro（10.0.26300） |
| 浏览器 | Microsoft Edge 157.0.4341.46（Chromium 内核） |

### 1.4 测试方法

- **功能测试**：按页面和业务流逐项手工/自动执行；
- **数据层测试**：通过页面上下文调用 `DB` API，校验库存、金额、状态；
- **端到端测试**：Playwright 模拟真实点击、输入和页面跳转；
- **兼容性测试**：桌面端、移动端视口，Edge/Chromium；
- **静态检查**：`node --check` 检查脚本语法，脚本扫描 25 个 HTML 的内部链接、资源路径和重复 ID；
- **回归测试**：修复缺陷后重新执行全部自动化用例。

## 4 缺陷记录与修复

| 编号 | 严重程度 | 问题描述 | 原因分析 | 修复措施 | 状态 |
|---|---|---|---|---|---|
| BUG-01 | 高 | 所有二次确认弹窗点击“确定”后仍返回取消，导致删除、取消订单、停用用户等操作无效 | `modal.close()` 先触发 `onClose` 将 Promise 置为 `false`，随后 `resolve(true)` 被忽略 | 增加 `settled` 标志，先结算 Promise 再关闭弹窗 | 已修复 |
| BUG-02 | 中 | 演示预约日期比预期早一天，测试预约可能与初始数据“撞车” | 使用 `toISOString().slice(0,10)` 取 UTC 日期，在东八区凌晨/午夜会偏移 | 增加本地日期函数 `futureDateKey()`，按本地年月日拼接 | 已修复 |
| BUG-03 | 低 | 个人中心“用户名”输入框为空 | 对 disabled input 使用 `textContent` 赋值无效 | 改为设置 `input.value` | 已修复 |
| BUG-04 | 低 | 后台产品页筛选下拉框换行、占用过多高度 | `.select` 全局 `width:100%` 影响 `.table-filter` | 为 `.table-filter` 设置 `width:auto`，调整搜索框弹性宽度 | 已修复 |
| BUG-05 | 中 | 结算页显示含运费，订单总额未包含运费 | 创建订单时只汇总商品金额 | 订单增加 `subtotal` 与 `shippingFee`，总额统一计算 | 已修复 |
| BUG-06 | 低 | 购物车数量调整后事件重复绑定 | 每次重绘后重复 `addEventListener` | 改为 `layout.onclick` 覆盖式绑定 | 已修复 |
| BUG-07 | 低 | 后台列表弹窗保存后重复绑定搜索事件 | 保存后重新初始化页面，静态控件重复绑定 | 静态控件改用 `oninput/onchange/onclick` 覆盖式绑定 | 已修复 |

> 说明：BUG-01 是测试过程中发现的最严重问题，影响所有二次确认操作；修复后重新执行全部 65 项自动化检查，均通过。

## 5 性能与兼容性

### 5.1 性能观察

- 系统不依赖外部 CDN、字体和图片，全部资源来自本地，网络波动不影响演示；
- 首页图片使用经压缩的本地实景照片，单张约 100—500 KB；产品图和果园图按需加载；
- 本地服务器下页面切换通常在 1 秒内完成；
- Canvas 图表使用 `devicePixelRatio` 缩放，在高分屏上保持清晰；
- 后台列表默认每页 8—10 条，避免一次性渲染过多 DOM。

### 5.2 兼容性

| 浏览器/设备 | 结果 | 说明 |
|---|---|---|
| Microsoft Edge 157（桌面 1440×1000） | 通过 | 全量自动化测试与截图 |
| Chromium 内核浏览器 | 预期通过 | 仅使用标准 API；未单独安装 Chrome 实测 |
| 手机视口 390×844 | 通过 | 移动菜单、单列布局、表格横向滚动 |
| Firefox / Safari | 未实测 | 代码未使用浏览器私有特性，理论兼容；建议答辩使用 Edge/Chrome |
| 直接双击 HTML（file://） | 不推荐 | 部分浏览器会限制 localStorage 跨文件共享，建议使用本地服务器 |

## 6 测试结论

1. 系统前台 15 个页面、后台 10 个页面均可正常访问，无未处理脚本异常；
2. 购物、下单、库存扣减、订单取消、确认收货、预约、留言、后台 CRUD 等核心流程全部通过；
3. 权限控制有效，未登录用户和普通用户无法进入后台；
4. 桌面端和移动端布局可用，主要交互有明确反馈；
5. 自动化测试 65 项全部通过，发现的 7 个缺陷均已修复；
6. 系统满足毕业设计验收标准，可用于现场演示。

### 6.1 已知限制

- 演示版数据存储在浏览器 localStorage，换浏览器或清理缓存后数据会重置；
- 不支持多用户并发、真实支付、短信、物流和图片上传；
- 密码为明文存储，仅适用于教学演示；
- 未在 Firefox/Safari 上进行完整回归测试。

### 6.2 后续测试建议

- 增加服务端 API 后，补充接口测试、并发下单测试和权限穿透测试；
- 增加真实支付沙箱、物流回调、图片上传的集成测试，并逐步引入持续集成。
